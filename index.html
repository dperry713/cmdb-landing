THE PROBLEM & WHY THIS EXISTS

Most agent memory today is one of two extremes.

Either too dumb (vector-only similarity lookup) or too academic (research cognitive architectures). CMDB sits in the practical middle.

EXTREME 01 • TOO DUMB Cosine(q, v) only

Vector-Only Databases

They support similarity search, but that’s it. An agent using only a vector DB can "remember" similar states, but it cannot forget redundant observations, cannot consolidate recurring patterns into long-term knowledge, and cannot use activation dynamics to prioritize relevant memories.

  • × No temporal dynamics: A stale observation from 3 days ago scores identically to one from 3 seconds ago.
  • × No activation decay: No ACT-R power-law forgetting curve to surface frequently reinforced contexts.
  • × No surprise gating or consolidation: Loops saturate the index with identical idle frames.
EXTREME 02 • TOO ACADEMIC Research Prototypes

Research Cognitive Architectures

They often model temporal dynamics and consolidation, but they're typically academic prototypes. Windows-only, no drop-in API, no packaging, and zero consideration for production deployment. Integrating them into a runtime requires months of engineering work and deep expertise in arcane details.

  • ! No drop-in API or NuGet packaging: Tightly coupled to academic simulation loops and legacy runtimes.
  • ! Steep integration cliff: Months of refactoring before an autonomous agent can run in production.
  • ! No crash recovery guarantees: Lacks deterministic write-ahead logging or SIMD-accelerated retrieval.

THE SOLUTION • .NET 8 LIBRARY

A real memory hierarchy — not just a vector search endpoint.

Six tightly integrated subsystems engineered for deterministic latency, bounded memory growth, and autonomous agent longevity.

1. 3-Tier Cognitive Hierarchy

Structured lifecycle progression from immediate sensorimotor context to permanent behavioral schemas:

  • Working: FIFO ring buffer (cap: 32)
  • Episodic: State transitions + action/reward provenance + ACT-R decay
  • Semantic: Abstract schemas promoted from clusters ≥3; immune to age pruning

2. Surprise-Gated Ingestion

An embedded ONNX World Model predicts the next latent state ẑ_{t+1}. Transitions matching predictions without notable reward are pruned at ingestion, preventing memory saturation.

S = ||z_actual - ẑ_predicted||₂
Ingest iff S ≥ θ_surprise OR |r| ≥ 0.1

3. Two-Stage SIMD Retrieval

Stage 1: Hamming-bucket pre-filter + 1-bit Hamming distance (POPCNT).
Stage 2: INT8 scalar-quantized dequantization + SIMD cosine similarity (TensorPrimitives).

Score = 0.65·CosineSim + 0.20·tanh(0.2·A) + 0.15·min(S, 2.0)

4. Unsupervised Consolidation

Periodically clusters episodic memories by binary embedding hash. Clusters with ≥3 instances are synthesized and promoted to the Semantic tier.

Decay Pruning: expired + low activation + low surprise → purge

5. Crash Durability (WAL v2)

Every accepted transition, consolidation promotion, and pruning event is appended to a compact Binary v2 Write-Ahead Log with deterministic replay on startup.

walPath: "agent_memory.wal" → zero memory loss across restarts

6. Fully Configurable

Tune capacities, decay exponents, quantization scales, and promotion thresholds cleanly via CognitiveMemoryOptions without touching internals.

13 parameters • Default & WithSurpriseThreshold() factories

Compares the lowest byte of the first 64-bit binary code word (bucket = Binary[0] & 0xFF).

Candidates differing by >1 bucket index are skipped; survivors pass 1-bit POPCNT Hamming filter.

DROP-IN C# SDK • .NET 8

Clean, Idiomatic C# Integration in Minutes

Explore production integration patterns for long-running agents, multi-agent coordination, episodic tool recall, and counterfactual planning. 

using CognitiveMemory.Engine;
using CognitiveMemory.WorldModel;

var worldModel = new OnnxWorldModel("world_model.onnx", latentDim: 1024, useGpu: false);
using var cmdb = new CognitiveMemoryDatabase(
    walPath: "agent_memory.wal",
    worldModel: worldModel,
    compressor: new PayloadCompressor(),
    vectorDim: 1024
);

// Agent ingests state transitions throughout its lifetime
var record = cmdb.IngestTransition(
    prevLatent: prevLatent,
    actionId: 3,
    currentLatent: currentLatent,
    reward: 0.85f,
    payloadJson: "{\"event\":\"door_opened\"}"
);

// Agent recalls relevant memories during planning
var results = cmdb.Recall(queryLatent, topK: 3);
foreach (var result in results)
{
    // Use match score + payload for decision making
}
// Each agent gets its own CMDB instance
var agentCmdb = new CognitiveMemoryDatabase(
    walPath: $"agent_{agentId}_memory.wal",
    worldModel: worldModel,
    compressor: new PayloadCompressor(),
    vectorDim: 1024
);

// Shared world model for surprise gating
var worldModel = new OnnxWorldModel("world_model.onnx", latentDim: 1024);

// Agents can recall each other's relevant memories
var results = agentCmdb.Recall(queryLatent, topK: 5);
// Agent remembers tool usage events
cmdb.IngestTransition(
    prevLatent, actionId: toolId,
    currentLatent, reward: toolResultReward,
    payloadJson: JsonSerializer.Serialize(new { tool, result, duration })
);

// Later, recall relevant tool usages for few-shot prompting
var similar = cmdb.Recall(queryLatent, topK: 5);
foreach (var r in similar)
{
    // Include in prompt: "Previously, when facing similar situation, agent did X with result Y"
}
var planner = new AgenticPlanner(cmdb, worldModel);
long[] candidateActions = [1, 2, 3, 4];
long bestAction = planner.SelectBestAction(currentLatent, candidateActions);
// bestAction maximizes: anticipated utility + historical precedent + epistemic curiosity

SCENARIO 01 12+ Hour Runtime

Long-Running Autonomous Agent

An agent operating for 12+ hours needs memory that doesn't saturate with redundant observations, consolidates recurring patterns into long-term knowledge, and survives restarts.

How CMDB helps:
  • •Surprise gating prunes ~30–50% of redundant observations at ingestion
  • •Consolidation promotes frequently-reinforced clusters to Semantic tier (immutable, age-independent)
  • •WAL replay-on-restart ensures no memory loss across process restarts
  • •Activation decay prioritizes fresh, relevant memories over stale ones
SCENARIO 02 5-Agent Swarm

Multi-Agent System

Five agents need to share conceptual knowledge while maintaining individual memory contexts.

How CMDB helps:
  • •Each agent gets its own CMDB instance with isolated memory
  • •Shared ONNX World Model for consistent surprise gating
  • •Consolidation promotes common patterns across agents to their respective Semantic tiers
  • •Hamming-bucket pre-filter enables efficient cross-agent memory recall
SCENARIO 03 Dynamic Few-Shot Recall

Tool-Using Agent with Episodic Memory

An agent that uses tools needs to remember which tools worked in which situations for few-shot prompting.

How CMDB helps:
  • •Each tool usage is ingested as a MemoryRecord with tool ID and result payload
  • •Recall retrieves similar past tool usages for contextual few-shot prompts
  • •Cluster promotion (≥3 uses of same tool → Semantic tier) surfaces frequently-used tools
  • •Activation decay ensures recently-used tools are prioritized over obsolete ones
SCENARIO 04 World-Model Rollouts

Counterfactual Planning

An agent needs to evaluate candidate actions by grounding imagined trajectories in historical episodic memory.
